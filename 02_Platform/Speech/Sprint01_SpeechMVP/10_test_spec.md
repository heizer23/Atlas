# Test Spec — Speech — Sprint01_SpeechMVP

## Scope
Speech backend recording lifecycle (auth, intake, limits, reassembly, transcription orchestration, deletion) against a stubbed transcriber with no real OpenAI call, plus manual UI checks of the recorder in ClaudeConsole; real-model accuracy is out of scope (manual checklist in `02_Platform/Speech/docs/Manual_Accuracy_Checklist.md`).

Fixtures: the "sample recording" is a short valid webm generated by ffmpeg in conftest and split at arbitrary byte offsets into 3 chunks; the "fake transcriber" returns a fixed text and records the model, prompt, keywords and languages it was given. Settings are overridden in tests (token set, dummy OpenAI key set, small limits, temp dir).

## Scenarios

### Happy path: chunks reassemble and transcribe
- **Given:** a created recording and the three chunks of the sample recording uploaded in order
- **When:** stop is requested with expected chunk count 3
- **Then:** the response contains the fake transcript, model_used, and metrics with chunk_count 3, a positive audio_duration_ms and total_bytes equal to the sample size; the fake transcriber received a file whose bytes equal the original sample; the recording's temp files are gone afterwards

### Out-of-order arrival is reassembled by index
- **Given:** a created recording
- **When:** chunks are uploaded in order 2, 0, 1 and stop is requested with expected count 3
- **Then:** the transcribed file equals the original sample

### Duplicate chunk upload is idempotent
- **Given:** chunk 0 already uploaded
- **When:** chunk 0 is uploaded again with identical bytes, then once more with different-sized bytes
- **Then:** the identical re-upload succeeds without changing totals; the different-sized one is rejected as a conflict (CHUNK_CONFLICT)

### Gap is rejected and recoverable
- **Given:** chunks 0 and 2 uploaded
- **When:** stop is requested with expected count 3
- **Then:** the request is refused with MISSING_CHUNKS listing index 1 and no transcription happens; after uploading chunk 1 a second stop succeeds

### Cancel discards audio
- **Given:** a recording with two chunks uploaded
- **When:** the recording is cancelled, then cancelled again, then a chunk upload and a stop are attempted
- **Then:** both cancels succeed; the later calls fail with RECORDING_NOT_FOUND; no temp files remain; the transcriber was never called

### Cancel of an unknown id succeeds
- **Given:** an id that never existed
- **When:** cancel is requested
- **Then:** the request succeeds with no content

### Authentication: missing or wrong token
- **Given:** a configured speech token
- **When:** each endpoint (except health) is called with no token header, then with a wrong one
- **Then:** every call is refused (UNAUTHORIZED) and no recording is created; the correct token is accepted

### Authentication: unconfigured service fails closed
- **Given:** settings with an empty speech token
- **When:** any non-health endpoint is called, even with some token header
- **Then:** the call is refused with SPEECH_NOT_CONFIGURED

### Health needs no token
- **Given:** any configuration
- **When:** the health endpoint is called without a token
- **Then:** it reports ok and reveals no configuration values

### Unsupported audio type
- **Given:** a valid token
- **When:** a recording is created with mime type text/plain
- **Then:** it is refused with UNSUPPORTED_MIME

### Oversized chunk
- **Given:** a recording and a max chunk size lowered to a few KB
- **When:** a larger chunk is uploaded
- **Then:** it is refused with CHUNK_TOO_LARGE and the recording stays usable for smaller chunks

### Too many chunks and too many bytes
- **Given:** limits lowered to 3 chunks and a small total byte cap
- **When:** a chunk with index at the chunk limit is uploaded; separately, uploads push the total beyond the byte cap
- **Then:** the first is refused with TOO_MANY_CHUNKS; the second is refused with RECORDING_TOO_LARGE and the recording and its files are deleted

### Too many concurrent recordings
- **Given:** max active recordings lowered to 2 with two open recordings
- **When:** a third is created
- **Then:** it is refused with TOO_MANY_RECORDINGS; after cancelling one, creation succeeds

### Over-long recording
- **Given:** max duration lowered below the sample's length
- **When:** all chunks are uploaded and stop is requested
- **Then:** it is refused with RECORDING_TOO_LONG, the transcriber is not called and the recording is deleted

### Undecodable audio
- **Given:** a recording whose chunks contain random bytes
- **When:** stop is requested
- **Then:** it is refused with INVALID_AUDIO, the transcriber is not called and the recording is deleted

### Vocabulary defaults and per-request override
- **Given:** a default vocabulary of prompt "P0", keywords ["k0"], languages ["en"]
- **When:** stop is requested (a) with no vocabulary fields, (b) with keywords ["k1","k2"] only, (c) with languages [] and prompt ""
- **Then:** the fake transcriber receives (a) all defaults, (b) default prompt and languages but keywords k1,k2, (c) empty prompt and no language, default keywords kept

### Fallback model mapping
- **Given:** a fake upstream that rejects the primary model as unknown and accepts the fallback
- **When:** stop is requested with keywords ["k1"]
- **Then:** the result reports the fallback model with fallback_used true, and the fallback request carried k1 folded into the prompt text rather than as a keywords field

### Upstream failure retains audio for retry
- **Given:** a fake upstream failing with a server error for both models
- **When:** stop is requested, then (after the upstream recovers) stop is requested again
- **Then:** the first call is refused with TRANSCRIPTION_FAILED; the second succeeds without re-uploading chunks; after success the files are deleted

### Upstream timeout
- **Given:** a fake upstream slower than the configured upstream timeout
- **When:** stop is requested
- **Then:** it is refused with TRANSCRIPTION_TIMEOUT and the recording is retained

### Silence yields an empty successful transcript
- **Given:** a fake upstream returning empty text
- **When:** stop is requested
- **Then:** the call succeeds with an empty transcript

### Idle recordings are reaped
- **Given:** a recording with chunks and an idle TTL elapsed (simulated clock)
- **When:** the reaper runs
- **Then:** the recording and its files are gone and later calls return RECORDING_NOT_FOUND

### Startup sweep
- **Given:** leftover files in the temp directory from a previous process
- **When:** the store is created
- **Then:** the directory is empty

### Secrets never leak
- **Given:** a sample run covering success and an upstream failure with the key and token set to recognizable values
- **When:** responses and captured log output are inspected
- **Then:** neither value appears anywhere, and the transcript text does not appear in logs

### [UI — manual] Dictate into ClaudeConsole without disturbing typed text
- **Given:** an active Console session on desktop Chrome over HTTPS, speech token already entered, the message box containing "fix the bug in " with the caret placed after "fix"
- **When:** the user taps the server mic button, speaks one sentence, taps it again
- **Then:** a transcribing indicator shows, then the sentence appears inserted at the caret with spaces separating it from neighbouring text, all prior text intact, the caret after the inserted text, and nothing is sent to Claude

### [UI — manual] Token prompt on first use and after rejection
- **Given:** no stored speech token
- **When:** the user taps the server mic button
- **Then:** an inline token field appears instead of recording; after entering a valid token recording starts without leaving the page; entering a wrong token shows an authorization error and asks again

### [UI — manual] Pause, resume and cancel on Android
- **Given:** Android Chrome over HTTPS, recording running for over 30 s (so at least one chunk has been uploaded)
- **When:** the user pauses for several seconds, resumes, speaks more, then in a second attempt starts a recording and taps cancel
- **Then:** elapsed time stops while paused; the finished transcript contains speech from before and after the pause with no gap at the chunk boundary; after cancel nothing is inserted, the mic is released and the browser mic indicator disappears

### [UI — manual] Mutual exclusion with browser dictation
- **Given:** the Console input with both mic buttons visible
- **When:** server recording is active, then browser dictation is active
- **Then:** while one is active the other is disabled; Send remains manual

### [UI — manual] Empty and error outcomes
- **Given:** a recording of silence, then a recording made with the Speech container stopped
- **When:** the user stops each
- **Then:** silence shows a neutral "No speech detected" notice and inserts nothing; the stopped service shows a readable error, inserts nothing, and the typed text is unchanged
