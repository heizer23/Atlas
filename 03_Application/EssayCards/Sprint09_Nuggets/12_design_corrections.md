# Design Corrections — EssayCards (Sprint09_Nuggets)

## Applied Changes

1. **Character-class mismatch between `SLUG_LIKE_RE` and `extract_nugget_keys`'s reference regex**
   - Review Source: `11_design_review.md` Confirmed Problem 1 / Minimal Change Set item 1
   - Files Updated: `10_architecture.json` (§contracts.invariants, internal_flow step 1, deferrals.application_implementer, deferrals.test_writer, deferrals.reviewer, deferrals.application_implementer's `tests/fixtures.sql` bullet, §risks), `10_scaffolding.json` (`backend/ingest.py`'s `extract_nugget_keys` public-object entry, `tests/fixtures.sql` role, `tests/test_ingest.py` new test entry), `10_test_spec.md` (new scenario)
   - Change: `extract_nugget_keys`'s reference-extraction regex character class was changed from `[a-z0-9_-]+` to `[a-zA-Z0-9_-]+`, matching `SLUG_LIKE_RE` exactly, so every valid `nugget_key` (mixed case included) is referenceable from a `[[nugget:key]]` reference. Resolution against a captured key remains exact-match/case-sensitive — only the accepted character set changed, not comparison semantics. The now-resolved risk entry describing this mismatch was removed from `10_architecture.json §risks`. Added a `tests/test_ingest.py` test-entry stub, a `10_test_spec.md` scenario, and a fixtures.sql note for a mixed-case fixture nugget.
   - Note: `00_draft.md §2` still quotes the original lowercase-only regex illustratively. The review's Required Fix for this item did not ask for a `00_draft.md` edit (unlike item 2, which explicitly did), so `00_draft.md` was left unchanged per this agent's mandate (design artifacts only, plus the draft only when the review explicitly requires it). Flagged under Notes below for human attention.

2. **Main-spine-only nugget references have no title-resolution path (R-CON-AL-03 / Hard Rule Violation 1)**
   - Review Source: `11_design_review.md` Hard Rule Violation 1 / Minimal Change Set item 2
   - Files Updated: `10_architecture.json` (§contracts.provides for the three essay-detail/export endpoints, §contracts.invariants — `extract_nugget_keys`/titleMap invariant, new internal_flow step 20 `main_spine_nuggets_resolution`, interfaces.exposed_surfaces for `GET /essays/{id}`, `GET /essays/{id}/export`, `GET /essays/{id}/sections/{section_id}/export`, deferrals.application_implementer, deferrals.ui_implementer, deferrals.test_writer, deferrals.reviewer, deferrals fixtures bullet), `10_scaffolding.json` (`essays.py` role/`ESSAY_SCHEMA`/new `_main_spine_nuggets` private object, `src/ShellEntry.tsx` role point 2, `tests/test_essays.py` two new test entries), `10_test_spec.md` (two new scenarios)
   - Change: Chose the additive fix (option b from the review's Either/Or) — a new server-computed `main_spine_nuggets: [{nugget_key, title}]` field, resolved via `extract_nugget_keys(main_spine_markdown)` against `essaycards.nuggets` independent of section co-reference (new private helper `_main_spine_nuggets`, internal_flow step 20), added to `GET /essays/{id}`, `GET /essays/{id}/export`, and `GET /essays/{id}/sections/{id}/export`. Frontend `titleMap` for `main_spine_markdown` is now the union of every section's `nuggets` field AND this new `main_spine_nuggets` field, so a nugget referenced only in the main spine resolves to a title instead of rendering as `nugget-missing`. This does not restrict authoring (no new ingest-time validation was added) and reuses the existing join-helper pattern (`_nuggets_by_section`).

3. **Missing UI half of the `nugget_id` round trip (R-CON-AL-05 / Hard Rule Violation 2)**
   - Review Source: `11_design_review.md` Hard Rule Violation 2 / Minimal Change Set item 3
   - Files Updated: `10_architecture.json` (§contracts.provides for `GET /essays/{id}/questions`, new invariant on the QuestionOverviewView edit-form nugget control, new internal_flow step 21 `question_row_nugget_id_and_edit_ui`, interfaces.exposed_surfaces for `GET /essays/{id}/questions`, deferrals.application_implementer, deferrals.ui_implementer, deferrals.test_writer, deferrals.reviewer), `10_scaffolding.json` (`essays.py` role/`QUESTION_SCHEMA`, `src/ShellEntry.tsx` role point 8 (TS types) and new point 9, `tests/test_essays.py` new test entry), `10_test_spec.md` (new HTTP scenario + new `[UI — manual]` scenario)
   - Change: Chose the minimal-UI fix (option a from the review's Either/Or) — `GET /essays/{id}/questions` rows now carry `nugget_id` (nullable), and `QuestionOverviewView`'s existing per-question edit form gains a nugget `<select>` (options from `GET /nuggets`, plus a "No nugget" entry, initialized from the row's `nugget_id`). Save always sends `card.nugget_id` explicitly (chosen id or JSON `null`, never omitted) through the existing `POST /flashcards/upsert` call — no new endpoint, reusing the already-correct backend tri-state handling. This was chosen over declaring the gap a non-goal because the review characterized it as an unnoticed omission (backend built specifically to support it) rather than a deliberate scope decision, and the review itself described the UI fix as "minimal," reusing an existing form and existing endpoint.

## Unchanged by Design
All sections of `10_architecture.json`, `10_scaffolding.json`, and `10_test_spec.md` not touched by the three items above were preserved verbatim — including the nuggets router (7 endpoints), the `section_nuggets` resync mechanism, the ownership/cascade risk documentation, the flashcard-exploration context branch, the examination `nugget_versions` echo-through and `nugget_freshness_flags` helper, all non_goals, all deferred_decisions, and the PROCESS DEVIATION risk entry regarding `00_architecture/` staleness. `10_schema.sql` required no changes — none of the three corrections need a new table, column, or constraint (the `main_spine_nuggets` field and the `nugget_id` question-row field are both computed/read at request time from existing columns; the regex fix is Python-only).
